NaijaCart - Portfolio 3 - Concurrency Test Results
Test: Two sessions try to buy Product 1 (Laptop Stand) at the SAME TIME
Method: SELECT ... FOR UPDATE (pessimistic row lock)
Starting stock: product_id=1, name='Laptop Stand', stock_quantity=50

--- SESSION A (Terminal 1) ---
BEGIN;
BEGIN
SELECT stock_quantity FROM products WHERE product_id = 1 FOR UPDATE;
 stock_quantity

             50
(1 row)

--- SESSION B (Terminal 2, while Session A still open) ---
BEGIN;
BEGIN
SELECT stock_quantity FROM products WHERE product_id = 1 FOR UPDATE;
-- (no output - session blocks here, waiting for Session A lock)

--- SESSION A finishes ---
UPDATE products SET stock_quantity = stock_quantity - 50 WHERE product_id = 1;
UPDATE 1
COMMIT;
COMMIT

--- SESSION B unblocks ---
 stock_quantity

              0
(1 row)
-- Session B now sees 0, not 50. So it cannot buy 50 again.
ROLLBACK;
ROLLBACK

--- FINAL VERIFICATION ---
SELECT product_id, name, stock_quantity FROM products WHERE product_id = 1;
 product_id |     name      | stock_quantity
------------+---------------+----------------
          1 | Laptop Stand  |              0
(1 row)

Conclusion: FOR UPDATE worked. Without lock, both sessions would have read 50.
With lock, only Session A succeeded. Final stock = 0, no overselling.
