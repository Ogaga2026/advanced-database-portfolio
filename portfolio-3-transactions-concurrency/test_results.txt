NaijaCart - Portfolio 3 - Concurrency Test Results
Test: Two sessions try to buy Product 1 (Laptop Stand) at the SAME TIME
Product: product_id=1, name='Laptop Stand', starting stock_quantity=50
Method: SELECT ... FOR UPDATE (pessimistic row lock)

--- SESSION A (Terminal 1) ---
BEGIN;
SELECT stock_quantity FROM products WHERE product_id = 1 FOR UPDATE;
-- Output: 50
-- Row locked by Session A

--- SESSION B (Terminal 2, while Session A still open) ---
BEGIN;
SELECT stock_quantity FROM products WHERE product_id = 1 FOR UPDATE;
-- Output: (WAITS / HANGS - does not return)
-- Proof: Row is locked. Session B is blocked until Session A finishes.

--- SESSION A finishes ---
UPDATE products SET stock_quantity = stock_quantity - 50 WHERE product_id = 1;
COMMIT;
-- Output: UPDATE 1, COMMIT
-- Stock now 0. Lock released.

--- SESSION B unblocks ---
-- Output: 0 (sees updated stock after Session A commit)
-- Session B needs 50 but stock is 0, so:
ROLLBACK;
-- Output: ROLLBACK - No overselling.

--- FINAL VERIFICATION ---
SELECT product_id, name, stock_quantity FROM products WHERE product_id = 1;
-- Output: product_id=1 | name=Laptop Stand | stock_quantity=0

Conclusion: FOR UPDATE worked. Without lock, both sessions would have
read 50 and both would have bought 50 = -50 stock (overselling).
With lock, only Session A succeeded. Final stock = 0, correct.
No price update was tested in this file - this test is stock locking only.
